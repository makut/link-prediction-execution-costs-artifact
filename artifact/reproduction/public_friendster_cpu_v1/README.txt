Portable public fullFriendster CPU7 v1

This is a NEW portable local rerun recipe around the exact CPU v2 scientific
sources. It does not require an author hostname, cluster, internal BASE path,
root admission, YT, historical output, old PID, private data or a model.
Default run_public_cpu.py prints a source-verified complete plan only. It does
not open graph inputs, import numerical packages, create outputs or launch jobs.

Supply ordinary local paths:
  --full-csr: the public FULL Friendster mixed GraphCSR directory; train CSR is
    rejected. All3 entire payload SHA/byte sizes, N=65,608,366, M=3,612,134,270,
    the actual neighbor-count header and source stat continuity are required.
    The two array files total14,973,404,016bytes including8-byte neighbor-count
    header; the third numeric payload,num_nodes.txt,adds9bytes.
    See top-level PUBLIC_COMMANDS.txt for public acquisition/regeneration.
  --wheel-packet: separate exact CPU pt22 asset,15,064,339bytes,
    SHA5e9edbdc067325cd0b41b5fb292e2cc7343cc535da87ff3bef720cbf85da38cf.
    It contains exactly two official cp310/pt22/cu121 native wheels and the
    original download manifest. These are distinct from PENCIL's pt25 stack.
  --python: supplied Linux x86_64 Python3.10, Torch2.2.2+cu121, NumPy1.24.4,
    SciPy1.10.1, Numba0.58.0, pip and venv. Its lexical venv interpreter path is
    retained; its actual package origins/bytes and inherited plain package
    sites are freshly observed. No base packages are installed or changed.
    The runner creates its own isolated venv and installs ONLY the two exact
    native wheels offline, --no-index --no-deps --ignore-installed. The original
    35 native/init/wrapper hashes, saint source blob, stack and1thread checks
    remain mandatory. CUDA_VISIBLE_DEVICES is empty; no GPU is requested.
  --out: fresh local experiment root, outside all input/source paths. Failures
    and partial conversion/environment outputs are retained; no automatic resume.
  --coordination-dir: same shared writable directory as PENCIL and all timing
    runs. PUBLIC_SYSTEMS_RUNNING.lock is held with flock and the common
    PUBLIC_SYSTEMS_ACTIVE.json uses O_EXCL with role/PID/start_ticks/nonce.
    Unknown, changed or unquiescent predecessors retain the marker and block
    BOTH runners. Only exact owned token plus confirmed quiescence removes it.
  --source-manifest-sha256: independently reviewed portable release pin; required
    for --execute. No historical source or original science byte is edited.

Example: substitute actual local paths and release pin:
  "$CPU_PY" "$REPRO_ROOT/public_friendster_cpu_v1/run_public_cpu.py" \
    --python "$CPU_PY" --full-csr "$FR_FULL" --wheel-packet "$CPU_NATIVE_WHEELS" \
    --out "$CPU_OUT" --coordination-dir "$TIMING_COORDINATION" \
    --source-manifest-sha256 "$CPU_SOURCE_PIN"
Review the plan; add --execute to the same command for a fresh whole run.

Exactly128 existing ordered sets from the pinned768-record E1 archive are
reselected by the unchanged preparation. All3 native arms (full clear,
persistent touched reset, unmodified torch_sparse direct) and physical
Numba32/64 x fixed scan/pairwise execute. Same1warmup+3repeats per case, seeded
native method order, exact target-removed edges/DRNL, ordered raw native
rows/columns/originalEIDs and actual nopython kernels are retained. All3 native
arms run in fresh sequential processes. No sampler, training or quality is run.

Only operational paths/host admission change. portable_worker.py calls the
UNCHANGED cpu_worker_v1.execute() with an explicit path layout; the original
internal main() BASE/hostname gate is not invoked. Its scientific functions,
Numba kernels, all8 native source files and converters remain byte-identical.
portable_environment.py only generalizes allowed roots to the supplied
interpreter's actual observed package sites. Whole source lineage is recorded.

Resource admission: Linux host with at least64GiB FREE scratch disk, adequate
RAM for the frozen48GiB converter/native work estimate, and an explicitly chosen
external sampled-memory guard (default180GiB, never above180GiB). Max total6hours.
No graph download/source copy occurs. Native int64 destination arrays need
29,421,941,096bytes (~27.4GiB) and persist under OUT/runtime/native_i64. The
persistent8N map costs524,866,928private logical bytes per worker. This is not a
PSS measurement or a shared/free workspace. Setup/native representation costs
must be amortized honestly; Numba32 reads the compact source directly.

All13 setup/science/final phases have owned clean-exit checks, whole sampled
V3 guard JSONL, bounded stdout4MiB/guard8MiB, same-source checks and finite
phase deadlines. Scratch retains1.5GiB reserve. Raw evidence is limited96MiB;
this explicit evidence budget excludes large runtime native arrays, installed
venv/wheels and Numba caches. All such runtime data stays under OUT/runtime,
is never packed as raw evidence, and is not silently deleted. Stop/exception
cleans only confirmed owned descendants. Full input and base/isolated env are
checked before/after. Failed/incomplete science cannot become a successful run.

Successful science writes OUT/results/SCIENTIFIC_TERMINAL.json and a bounded
OUT/public_cpu7_raw.tgz with every raw result/log/guard/exit and exact sources,
plus a SHA inventory. ARCHIVE_READY and later COMPLETE remain outside the tar
hash; the controller's own final OS exit is not invented. Local archived bytes
are not automatically uploaded/published. Different hardware produces new
measurements, not guaranteed historical timing values. Query timers exclude
conversion/JIT/warmup/content checks/one-time init; full clear stays in-call.
Native clones/original EIDs and Numba binary CSR differ in low-level output.
